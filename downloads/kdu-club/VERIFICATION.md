# 수정 및 검증 기록

## 기존 코드에서 수정한 부분

1. 개설 신청이 교수 심사 없이 승인되던 문제: 테이블 기본값을 pending으로 바꾸고 등록 INSERT에도 pending을 명시했습니다. 기존에 승인된 동아리의 상태는 유지합니다.
2. 가입 심사 권한 누락: 로그인 학생이 실제 승인된 동아리의 개설자인지 검사하며 타인 요청은 403으로 거부합니다.
3. 중복 알림: pending에서 상태가 바뀐 요청에만 알림을 기록합니다. UPDATE에 pending 조건을 넣고 변경된 행 수를 확인해 반복·동시 처리 시 중복 알림을 방지합니다. 교수 POST 처리 후 GET으로 리다이렉트합니다.
4. 알림 읽음 기능 추가: 알림 소유자의 요청만 is_read를 변경하며 홈은 읽지 않은 알림을 표시합니다.
5. 업로드 검증: 허용 확장자와 파일 헤더를 확인하고 요청 전체를 5MiB로 제한합니다. 오류는 400 또는 413이며 대표 이미지에는 PDF를 받지 않습니다. 공지 PDF는 파일 링크로 표시합니다. 파일 헤더 검사는 완전한 파일 파싱이나 악성코드 검사를 대신하지 않습니다.
6. DB 구조 불일치: schema.sql과 앱의 신청서 필드를 맞췄습니다. 기존 DB에는 삭제 없이 누락된 필드를 추가합니다.
7. 비밀번호 평문 저장: 기존 비밀번호를 해시로 변환하고 가입·로그인에도 해시를 사용합니다. 신규 회원가입은 비밀번호 8자 이상을 요구합니다.
8. POST 요청에 CSRF 토큰을 추가하고 검사합니다. 고정된 코드 내 세션 비밀 키를 제거하고 환경변수 또는 실행별 임의 키를 사용합니다.
9. 미승인 동아리는 신청자·교수만 상세 조회할 수 있으며, 개설 신청 상태는 학생 마이페이지에 표시합니다. 존재하지 않는 ID와 잘못된 심사 행동을 처리합니다.
10. DB와 업로드 경로를 app.py 기준으로 잡고 의존성 버전과 실행 안내를 추가했습니다.

## 실행 결과

`python -m unittest discover -s tests -v`: 10개 테스트 실행, 10개 통과.

- 동아리 개설 대기 → 교수 승인 → 공개 목록 반영 및 알림 1회
- 타 학생의 가입 심사 요청 거부, 개설자 심사, 신청자에게만 알림
- 알림 읽음 권한과 처리
- 검색·필터 정상 결과 및 따옴표/SQL 인젝션 입력
- 금지 확장자, 위장 확장자, 용량 초과 거부
- 첨부된 정상 PNG 업로드 및 PDF 공지 표시
- CSRF 누락 요청 거부
- 가입 비밀번호 해시, 잘못된 비밀번호 거부, 정상 로그인
- 존재하지 않는 ID 및 잘못된 심사 행동
- 주요 학생·교수 화면 렌더링

추가 확인: 실제 서버의 홈, 로그인, 특수문자 검색 HTTP 응답 통과. 첨부 DB와 수정본 DB의 각 테이블 데이터 수 유지 확인, 기존 비밀번호로 해시 검증 통과. 첨부 DB 복사본으로 앱을 두 번 로딩하여 마이그레이션 반복 실행 통과. requirements.txt 재설치 통과.
