# KDU 동아리 — 데스크톱 UI 구현본

경동대학교 동아리 과제입니다. 제공받은 D01–D12 화면 이미지를 바탕으로 기존 Flask·SQLite·Jinja2 코드를 보완했습니다. 모바일 UI는 작업 범위에서 제외합니다.

## 빠른 실행 — Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

## 빠른 실행 — macOS/Linux

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

브라우저 주소창에서 `http://127.0.0.1:5000/login`을 열면 됩니다. 시연 계정:

| 역할 | 아이디 | 비밀번호 |
|---|---|---|
| 학생·코딩클럽 개설자 | kdu_student | sample1234 |
| 교수·개설 심사 전용 | kdu_professor | sample1234 |

`python app.py`는 `instance/demo.db`와 `instance/demo-attachments`를 사용합니다. 처음 실행할 때만 샘플을 생성하고 재실행 시 작성 내용을 유지합니다. 기존 `database.db`는 덮어쓰지 않습니다. `KDU_DATABASE`를 명시한 경우 해당 DB를 사용하며 시연 DB로 바꾸지 않습니다. 모집 기간과 일정은 샘플 생성 시점에 맞춰 생성됩니다. 기간이 지나면 운영 관리에서 새 모집 기간을 설정하세요.

기존 첨부 DB를 사용하려면 `python app.py --original`로 실행하세요. 기존 계정과 데이터는 유지됩니다. 신규 빈 DB 초기 계정은 학생 `20211234 / 1234`, 교수 `prof1 / 1234`이며 실제 기존 DB의 계정과 다를 수 있습니다. 기존 동아리는 모집 기간·정원이 없으면 신규 가입을 받지 않으므로 개설자가 운영 관리에서 설정해야 합니다.

포트가 사용 중이면 `python app.py --port 5001`처럼 다른 포트를 사용하세요.

## 화면과 기능

| 화면 | 경로 | 구현 내용 |
|---|---|---|
| D01 로그인 | `/login` | 자체 계정 로그인, 오류 안내, 학생 회원가입, 로그아웃 |
| D02 탐색 | `/` | 이름·소개·캠퍼스 검색, 분류 필터, 모집 중 필터, 찜, 빈 결과 |
| D03 상세 | `/clubs/<id>` | 소개·공지·다가오는 일정·공개/비밀 Q&A, 찜, 모집 상태·신규 정원 |
| D04 가입 신청 | `/clubs/apply/<id>` | 필수 신청 항목, 입력 검증, 모집·정원·중복 신청 제한 |
| D05 내 활동 | `/student/mypage` | 가입·대기·찜 집계, 탭, 신청 취소, 결과 팝업, 개설 현황 |
| D06 알림 | `/notifications` | 전체/안읽음, 개별·전체 읽음, 결과 이동 시 읽음 처리 |
| D07 개설·재신청 | `/clubs/register`, `/clubs/<id>/resubmit` | 공식 등록 정보·최소 20명·12개월 계획·준비 PDF·보완 후 재검토 |
| D08 운영 정보 | `/clubs/<id>/manage` | 승인 후 소개·활동 정보·모집 기간·정원 수정, 조기마감, 새 모집 |
| D09 가입 심사 | `/clubs/<id>/members` | 신청 선택, 필수 반려 사유, 가입 승인, 처리 완료·부원 목록 |
| D10 공지 | `/clubs/<id>/posts` | 작성·수정, 최대 3개 첨부, 개별 삭제, 업로드 실패 시 내용 보존·재시도 |
| D11 일정 | `/clubs/<id>/schedules` | 등록·수정·날짜순 목록, 종료 검증, 삭제 확인·취소 |
| D12 교수 | `/professor/dashboard` | 준비 PDF 수동 검토, 보완 요청, 사전 확인 완료(학교 최종 승인과 별개) |

학생 개설자만 승인된 동아리를 운영할 수 있습니다. 교수 계정은 등록 서류 사전 검토와 준비 PDF 조회·공식 안내만 이용하며 동아리 운영·가입 심사에는 접근할 수 없습니다. 승인된 동아리명·분류는 운영 화면에서 변경하지 않습니다. 비밀 질문은 질문자와 개설자만 조회하며, 공개 질문은 익명으로 표시합니다. 가입 심사 화면에서는 학번·연락처를 표시하지 않습니다.

## 모집과 알림 규칙

학교 시각(Asia/Seoul)을 기준으로 모집을 판단합니다. 날짜 입력은 `YYYY.MM.DD HH:MM`(24시간제)이며 서버는 ISO 형식으로 저장합니다. 신규 신청은 승인된 동아리의 현재 모집 기간에만 가능하고 정원이 찼거나 조기마감하면 제한됩니다. 마감 후 접수된 기존 신청은 계속 심사할 수 있습니다.

이번 모집 승인 수와 전체 부원 수를 분리합니다. 정원을 이번 모집 승인 인원보다 작게 저장할 수 없습니다. 새 모집은 기존 모집이 마감되고 대기 신청을 모두 처리한 뒤 시작할 수 있습니다. 승인·신청은 DB 쓰기 잠금 안에서 조건을 다시 검사하여 중복 신청과 동시 승인 시 정원 초과를 방지합니다.

가입 결과와 등록 서류 사전 검토 결과에만 인앱 알림을 기록합니다. 같은 심사를 반복해도 알림을 추가하지 않습니다. 공지·일정·Q&A 답변 알림, 탈퇴·회장 위임, 학교 SSO는 제공된 화면에 따라 이번 범위에서 제외합니다.

## 첨부 파일

PDF, HWP, DOCX, JPG/JPEG, PNG를 파일당 10MiB 이하, 공지당 최대 3개까지 첨부할 수 있습니다. 요청 전체는 32MiB로 제한합니다. 이미지와 DOCX는 형식 구조를 검사하며 PDF/HWP는 헤더를 검사합니다. 파일 이름은 표시용이고 저장 시 임의 이름을 사용합니다. 첨부는 `instance/attachments`에 보관하며 서버의 다운로드 경로를 통해 제공합니다.

업로드는 본문 저장과 분리되어 있습니다. 실패한 업로드는 제목·본문·기존 첨부를 변경하지 않습니다. 기존 첨부 삭제는 공지 저장 시 반영되고 취소하면 유지됩니다. 파일 내용·형식 검사는 악성코드 검사나 문서 전체 유효성 검사를 대신하지 않습니다.

## DB와 설정

기존 DB를 실행 전 백업하세요. 앱 시작 시 누락된 필드를 추가하고 평문 비밀번호를 해시로 변환합니다. 이전 공지의 단일 첨부는 삭제·복사 없이 새 첨부 목록으로 연결합니다. `init_db()`와 `schema.sql`은 초기화용이므로 기존 데이터가 있는 DB에 직접 실행하지 마세요.

`KDU_DATABASE`와 `KDU_ATTACHMENT_FOLDER`로 저장 위치를 바꿀 수 있습니다. `KDU_SECRET_KEY`를 환경변수로 설정하면 재시작 후에도 세션 키가 유지됩니다. 미설정 시 실행별 임의 키를 사용해 재로그인이 필요합니다. 키를 코드나 Git에 저장하지 마세요. 런타임 DB와 첨부 폴더는 Git에서 제외합니다.

## 검증

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Windows에서는 `.venv/bin/python` 대신 `.\.venv\Scripts\python.exe`를 사용하세요. 자동 테스트 42개가 임시 DB에서 통과했습니다. 기존 데이터는 건드리지 않습니다. Chromium·Playwright로 D01–D12와 팝업/오류 상태를 검증했고 콘솔 오류는 없었습니다.

브라우저 QA를 다시 실행하려면 Node.js와 Playwright 및 Chromium이 필요합니다. 별도 작업 디렉터리에 Playwright를 설치하고 `NODE_PATH`를 해당 `node_modules` 경로로 설정하거나 현재 프로젝트에서 Playwright를 사용 가능하게 준비한 뒤 다음을 실행하세요.

```sh
.venv/bin/python qa/run_browser_checks.py
```

`CHROMIUM_PATH`로 브라우저 경로를 지정할 수 있습니다. QA 실행기는 임시 샘플 DB와 서버만 생성하고 종료합니다. 캡처는 `qa/screenshots`, 결과는 `qa/browser-results.json`에 저장합니다. 자세한 검증 범위는 `VERIFICATION.md`, 디자인 확인 범위는 `design-qa.md`를 참고하세요.

## 로그인 후 500 오류 수정

Windows의 시스템 시간대 데이터 유무와 관계없이 한국 시각을 계산하도록 수정했습니다. 모집 날짜가 비어 있거나 잘못 저장된 경우에는 미설정 상태로 표시하고 신청을 제한합니다. 새 DB 초기화 파일은 UTF-8로 읽습니다. 기존 DB를 삭제하거나 재생성할 필요는 없습니다. 서버를 종료하고 최신 app.py로 재실행한 뒤 다시 로그인하세요. 기존 계정은 python app.py --original로 사용할 수 있습니다.

## 공식 모집 공고 반영

기준 자료는 사용자가 제공한 `2026학년도 메트로폴캠퍼스 동아리 모집 공고.pdf`와 `동아리 등록 서식.hwpx`입니다. 원문은 메뉴의 **공식 등록 안내**에서 내려받을 수 있습니다.

- 등록 자료 작성·사전 검토는 날짜와 관계없이 이용합니다. 공식 공고의 서식·자격·서류 검토 기준을 반영하며, 학교 접수와 최종 승인은 별도입니다. 동아리별 신규 부원 모집 기간 설정은 유지합니다.
- 신규 등록 준비는 **메트로폴캠퍼스** 기준으로만 받습니다. 다른 캠퍼스의 기존 샘플·사용자 데이터는 변경하지 않습니다.
- 단체명·설립일·설립 목적·주요 활동·지도교수·회장/대표자·등록 회원 수 **최소 20명**, 1–12월 활동 내용·기대효과를 작성합니다. 등록 회원 수는 사이트의 이번 모집 신규 정원과 별개입니다.
- 신규·기존 모두 서식 1–4, 기존 동아리는 서식 5 실적 보고서가 추가로 필요합니다. 회칙과 전체 회원 명단은 준비 PDF에 포함합니다. 회원 명단에는 직책·학과·학년·학번·성명·연락처를 기재합니다.
- 회원의 재학 자격·결격 사유, 두 개 이상의 동아리 참여 시 별도 기재, 실제 회장/지도교수 서명을 확인합니다. 폐쇄 동아리 관련 신청은 이전 명칭·목적·팀원 중 동일한 항목이 없음을 확인해야 합니다.
- 서류를 순서대로 정렬해 **동아리명(대표자 성명).pdf**로 합쳐 첨부합니다. 사이트 보관용 한도 10MiB는 앱의 기술적 제한이며 공고의 제출 용량 규정이 아닙니다. 암호화되거나 손상된 PDF는 받지 않습니다.
- 업로드된 등록 PDF는 `instance/registration-packets`에 비공개 보관하고 **신청자·앱 교수 검토 계정만** 내려받을 수 있습니다. `KDU_REGISTRATION_FOLDER`로 경로를 바꿀 수 있습니다. 응답은 private/no-store이며 Git·다운로드 배포 ZIP에 실제 등록 준비 자료를 포함하지 않습니다.
- 교수는 PDF의 필수 서식·최소 인원·자격·중복 참여·서명을 직접 확인했다고 표시해야 사전 확인을 완료할 수 있습니다. 서류가 없는 예전 과제용 신청은 보완 요청 후 다시 준비합니다. 내용 진위·학생 신분·공식 서명은 자동 인증하지 않습니다.
- **학교 이메일 제출·선발·최종 승인·동아리실 배정은 별도**입니다. 실제 제출은 신청자가 공고의 동아리 부장 이메일로 직접 진행합니다. 이 앱은 이메일을 발송하지 않습니다.
- 신규 동아리실은 1학기 성과 평가 후 2학기에 배정되며 공간 부족 시 공동 사용 가능하다고 안내합니다. 사이트의 활동 장소 입력은 학교 배정 기록이 아닙니다.
- 우수동아리 평가 배점(활동실적 55·수상 20·회원 수 15·기타 10)과 유형별 변경 기준을 안내합니다. 점수·장학금·자격을 자동 확정하지 않습니다.

회비·활동 요일·가입 조건은 기존 웹사이트의 운영 정보이며 공고에서 별도로 정한 필수 기준이라고 주장하지 않습니다. 학교 계정 인증과 학교 접수 시스템 연동은 구현하지 않았습니다.

업데이트는 템플릿과 의존성도 포함하므로 **app.py만 교체하지 말고 최신 프로젝트 전체**를 사용하세요. 기존 DB와 instance 폴더는 먼저 보존하고 새 버전으로 실행하면 누락된 필드·테이블만 추가합니다. 새 빈 환경은 `pip install -r requirements.txt` 후 `python app.py`로 실행합니다.

내 활동은 **신청 현황 / 개설 신청** 두 탭입니다. 신청 현황에 가입 신청 결과·가입한 동아리·찜 목록을 함께 표시하고, 개설 신청에 등록 준비·사전 검토·PDF 다운로드·재신청·운영 관리 이동을 모았습니다.
