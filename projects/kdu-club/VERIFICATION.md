- 공지 작성·수정과 10MiB/최대 3개 첨부를 구현했습니다. 업로드를 분리하여 실패 후 제목·본문·기존 첨부를 유지합니다.
- 일정 등록·수정·삭제 확인과 취소, 시간 검증 및 날짜순 목록을 구현했습니다.
- 공개·익명 및 비밀 Q&A를 구현하고 비밀 질문을 서버 조회 단계에서 제한했습니다.
- 검색은 파라미터 바인딩을 사용합니다. 비밀번호 해시·CSRF를 유지하고 기존 DB 보완 작업을 반복 가능하게 만들었습니다.

## 로그인 후 오류 대응 — 최신 검증

배포 ZIP의 기존 DB와 시연 DB는 현재 Linux 환경에서 로그인 이후 탐색·마이페이지·상세·알림 응답이 정상입니다. 사용자의 실제 Traceback은 아직 전달받지 않아 개별 환경의 정확한 원인은 확정하지 않았습니다.

확인한 실패 경로: 시스템 시간대 DB가 없을 때 Asia/Seoul 조회 실패, 모집 날짜가 NULL일 때 문자열 비교 TypeError, Windows 기본 CP949 인코딩으로 초기화 SQL을 읽을 때 디코딩 실패. 현재 한국 시각의 UTC+09:00 계산, 미완성 모집 정보 처리, 명시적 UTF-8 읽기로 보완했습니다.

시간대 DB 없음·초기화 인코딩·빈 모집 날짜·잘못된 모집 값 회귀 검증을 추가하여 **35개 실행 / 35개 통과**했습니다. Chromium D01–D12 기능 검사도 별도 임시 프로젝트에서 통과했습니다. 사용자 환경의 동일 증상 해결 여부는 실제 로그와 재실행 결과로 확인해야 합니다.
